# Taste Skill UI 改版

来源：Leonxlnx/taste-skill，v2.1.5，提交12af471f627f866411b4bd785b19646d3672784c，MIT。个人技能已按原项目目录安装；网站只新增设计实现，不向浏览器加载设计技能脚本。

采用 app-screens 工作流、editorial-greeting、seed 20261103，保留已托管的 Noto Sans SC 字体。没有重新抽取方向。页面问题：我该接着学哪一课，工作中卡住时从哪里查？

真实对象：课程与通过证据、当前讲解页与草稿、Linux 管道、页面请求、Nginx 日志、DM8 业务表、日语分级、原文书籍、行测错题。全部概览数字从现有数据计算。当前账号为零时显示0，不生成连续学习天数或虚构成绩。

产品特征：知行的理解、动手、检验构成继续学习区；网页请求到日志、数据库的证据链构成排障入口。运维仍是首页主线，其他领域保留入口。桌面开放侧栏、1100px内容；平板折叠导航；手机底部导航与单列。

改前问题：大标题与重复编号占据首屏；黄黑导航对比强于内容；课程入口过深；不同模块控件间距与形状不一致。优先改进：首屏接续动作、克制色彩与统一控件、响应式阅读与操作。

自动 inspector 使用独立浏览器控制，不符合当前环境的浏览器操作约束，因此不运行。改以受管浏览器在桌面、768px与390px宽度检查真实页面，并运行静态 app 规则扫描与课程回归。本轮静态扫描为0 FAIL、5 WARN；5个提示均命中用于移除旧装饰的选择器或 `backdrop-filter:none` 声明，保留这些重置是必要的。没有运行独立 inspector，也不将手工检查称为自动零失败。


## 验证与取舍

- 浏览器：1440px、768px、390px嵌入视口分别为1425、753、375px可用内容宽度（扣除滚动条），各自 scrollWidth 与 clientWidth 相等。检查了亮色首页、深色日语、书房、运维阶段筛选、行测菜单与错题反馈。
- 实际点选错答并提交，仍停留资料分析第1/4题；未解锁的4个后续阶段保持禁用。
- 既有 `civil.cjs`、`civil-path.cjs`、`learning-flow.cjs`、`operations-depth.cjs`、`local-progress.cjs`、`paged-classroom.cjs` 均通过。
- 三轮修订：修正侧栏文字对比；整合运维路线与学前指引，收起可展开目标；移除编号后重新定义课程行网格，避免标题被挤入窄列。
- 手工评审：下一步动作与主线明确，侧栏及阅读对比改善，三种宽度无横向溢出。局限：大量旧课程的内容页仍有不同长度的讲解，未逐一人工查看全部388节；未在真实手机硬件上验证。
- 所有数量来自站点数据与本设备记录；没有样例用户、虚构成绩或新增营销图像。采用应用界面规则，无图片与入场动画数量要求。
- 对照图位于 `docs/ui/`，设计抽取记录位于 `docs/taste-direction.json`。
